공개 주소: https://siskimmk-cpu.github.io/promo2-quiz/

- `index.html` — 화면(스타일 포함). `questions.js`, `app.js`를 불러온다. 파일을 바꾸면 `?v=` 값과 `window.BUILD` 값, 그리고 `version.json`의 v 값을 모두 같은 새 날짜시각(YYYYMMDDHHmm)으로 올린다. 그래야 예전 화면이 캐시된 기기도 자동으로 최신 버전으로 새로고침된다.

## 문항 형식 (QUESTIONS 배열 원소)
```js
{ id:'F19', sec:'F', style:'손해사정형', level:'고난도'(선택), tags:['조문'|'판례'|'개수형'|'괄호'|'사례'|'핵심숫자'...],
  q:'발문', case:'사례 지문(선택)', box:['ㄱ. ...','ㄴ. ...'](선택), boxTitle:''(선택),
  opts:['①','②','③','④'], ans:0~3, exp:'해설(\n 줄바꿈 가능)', ref:'근거 조문·판례·출처',
  why:['○/× 보기1이 맞거나 틀린 이유', '…보기2', '…보기3', '…보기4'] }  // 보기별 해설, opts와 같은 순서·개수
```
- sec: A 공제계약 일반, B 담보종목·면책, C 공제금 지급기준(이상 공제약관), D 보험계약법, E 손해사정이론, F 자배법, G 상식
- ID는 sec 문자 + 일련번호. 고난도는 `level:'고난도'`.
- **계산 문제는 만들지 않는다**(사용자 요청). 시험 공고 과목(자배법·손해사정이론·보험계약법·공제약관·상식) 범위의 개념·조문·판례·사례형만 출제한다.
- 숫자 오름차순 보기·개수형·괄호·합답형에는 해당 tag(핵심숫자/개수형/괄호) 또는 box를 넣어 보기 섞기에서 제외되게 한다.
- <보기> 항목 기호는 ㄱ·ㄴ·ㄷ 대신 **가·나·다·라·마**를 쓴다(사용자 요청).
- 정답 번호는 1~4번이 고르게(각 25% 안팎) 되도록 배치한다.
- 정답 위치(ans)는 고르게 분산.
- why(보기별 해설)는 모든 문항에 필수(현재 전 문항 작성 완료). ○/×는 그 보기 진술의 참·거짓 기준.
- 상식(G)은 시사상식(경제·IT·정치·사회·국제·환경 용어와 제도) 중심 + 교통·보험 법규.

## 출제 범위 (가장 중요)
시험 공고 과목 5개 안에서만 낸다. 범위 밖이면 아무리 좋은 문제여도 넣지 않는다.
- 자배법(F): 자동차손해배상 보장법·시행령·시행규칙, 자배법 제4조로 적용되는 민법 불법행위 규정(제750조~제766조)만, 관련 대법원 판례. 민법 총칙(일반 소멸시효 중단 등)·친권 등 가족법은 내지 않는다. 상속은 공제약관 지급기준(사망 위자료 청구권자는 민법상 상속규정에 따름)의 적용 문제로만 C 영역에서 낸다(2차 자동차보험 기출 17회 중 7회).
- 손해사정이론(E): 위험관리·보험이론·손해의 개념과 산정 원리·과실상계·손익상계·대위·손해배상 범위. 보험업법은 시험 과목이 아니므로 전혀 내지 않는다.
- 보험계약법(D): 상법 제4편 보험(통칙·손해보험·자동차보험·책임보험 중심, 인보험은 기본만), 약관규제법의 약관 해석·설명의무, 관련 판례.
- 공제약관(A·B·C): 2025. 8. 12. 개정 자동차공제약관과 그 지급기준(별표·자배법 시행령 별표 포함).
- 상식(G): 시사상식(정치·행정·경제·금융·IT·사회·국제·환경 용어와 제도)과 교통·보험 관련 상식(교통사고처리특례법, 도로교통법 핵심, 보험사기방지 특별법, 금융소비자보호법 기본). 정치는 제도·용어·사실(선거제도, 국회·정부 조직, 헌법기관, 법률 제정 절차, 정치 시사 용어 등)로만 내고, 특정 정당·인물에 대한 평가나 찬반이 갈리는 쟁점의 정답 판단은 내지 않는다. 역사·문화·스포츠·연예는 내지 않는다.
- 이 밖의 법(보험업법, 형법, 세법, 행정법, 개인정보 보호법, 여객자동차 운수사업법 등)과 회사 내부 규정(공제규정)·업무 매뉴얼은 출제하지 않는다. 단 상식(G)의 교통·보험 관련 상식은 예외.
- `ref`에는 반드시 그 과목의 근거(약관 조항, 상법·자배법 조문, 판례, 손해사정이론 단원)를 쓴다. validate.js가 과목별 근거 키워드를 검사한다.

## 매일 새 문제 공개 (rel)
- 문항에 `rel:'YYYY-MM-DD'`를 넣으면 그날 **한국시간 오전 9시(UTC 0시)**부터 보인다. 그 전에는 앱이 목록에서 뺀다.
- 그날 공개된 문항은 홈의 "오늘 공개된 새 문제" 카드로 모아 풀 수 있다. 업데이트 알림 시트도 뜬다.
- 매일 자동 작업(예약 작업)이 하루 3번 10문항씩 추가한다(아래 '매일 30문항 신설 계획' 참고). 과목 배분 기준은 시험 비중(자배법 12·손해사정 12·보험계약법 12·공제약관 12·상식 2)을 따르되, 문항 수가 적은 과목을 먼저 채운다. 상식은 이미 충분하므로 하루 0~1문항만.
- 이미 예약된 rel 날짜가 남아 있으면 그 다음 날짜부터 이어서 만든다(같은 날짜 중복 금지).
- 새 문항 작성 전 `tools/syllabus.md`에서 아직 다루지 않은 주제를 고르고, 기존 문항과 쟁점이 겹치지 않게 한다(`grep`으로 핵심어 확인).
- 조문·숫자는 반드시 국가법령정보센터 등 웹에서 현행 내용을 확인한다. 공제약관 수치는 2025. 8. 12. 개정 공제약관 기준(대차료 35%, 상실수익 호프만 계수, 농어업인 취업가능연한 70세 등).
- 교재·문제집 문장을 그대로 옮기지 않는다(저작권). 쟁점만 따와 새로 쓴다.
- 조문 표기는 `제3조 제1항`처럼 한글로 쓰고 `§`는 쓰지 않는다.

## 기출 빈출 표시 (hot)
- `hot:{t:'쟁점명', y:출제 회수, of:분석 회수}` — 손해사정사 1차 기출(제37~46회, 10회분)의 보험계약법·손해사정이론과 손해사정사 2차 자동차보험 기출(17개년)에서 같은 쟁점이 몇 회 나왔는지 센 값. 보험업법 문항은 집계에서 뺐다.
- y/of가 0.6 이상이면 "기출 빈출" 배지와 홈 "기출 빈출 쟁점" 묶음에 들어간다.
- 새 문항이 빈출 쟁점(고지의무·약관 설명의무·계약 성립·대위·피공제자 범위·과실상계 등)이면 같은 형식으로 hot을 붙인다.

## 로그인·관리자 (송무온과 같은 Supabase 서버)
- `auth.js`가 먼저 실행돼 로그인 → `quiz_me()`로 승인 상태 확인 → 승인됐으면 서버 학습기록을 합친 뒤 `app.js`를 불러온다.
- 사용자 명단은 `quiz_members`(송무온 `allowed_users`와 별도). 관리자 = 송무온 관리자(`is_admin()`).
- 학습기록은 `quiz_progress`에 계정별로 저장(기기 간 동기화). 관리자는 설정 → 사용자 관리에서 승인·해제·임시 비밀번호·학습 현황을 본다.
- DB 설정은 `tools/supabase_quiz.sql`을 Supabase SQL Editor에서 한 번 실행. 실행 전에는 `quiz_me`가 없어서 예전처럼 로그인 없이 열린다.
- 진급시험에서 만든 계정은 user_metadata.app='promo2'로 표시되고, 송무온 승인 목록에서는 숨긴다.
